# Lab 1: DevOps Foundations & Continuous Integration

## Question 2: CI/CD Workflow Report

### 1. Introduction

Continuous Integration and Continuous Deployment (CI/CD) are DevOps practices that automate software integration, testing and deployment. This experiment demonstrates a CI/CD workflow using Git, GitHub, Jenkins and a Python Flask application.

### 2. Architecture

The workflow consists of the following components:

- Developer: Creates and modifies application source code.
- Git: Tracks changes and manages branches.
- GitHub: Hosts the source code repository.
- Jenkins: Automates the CI/CD pipeline.
- Python and Flask: Provide the application runtime.
- Pytest: Executes automated application tests.

### 3. Workflow Architecture

Developer → Git Repository → GitHub → Jenkins → Checkout → Build → Test → Package → Deploy → Health Check

### 4. Pipeline Stages

**Stage 1: Checkout**

Jenkins retrieves the latest source code from the GitHub repository's main branch.

**Stage 2: Build**

Jenkins installs the dependencies listed in requirements.txt using pip.

**Stage 3: Test**

Pytest executes the automated tests in tests/test_app.py.

Two tests are included:
- test_home: Verifies the home endpoint returns HTTP 200 and the expected application message.
- test_health: Verifies the health endpoint returns HTTP 200 and a healthy status.

**Stage 4: Package**

The Python compileall module checks and compiles the application source files.

**Stage 5: Deploy**

Jenkins launches the Flask application on port 5000 and performs an HTTP health check against the /health endpoint.
